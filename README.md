# Dev8StudioSite

> **เปลี่ยนความคิดของคุณ ให้กลายเป็นระบบที่ใช้งานได้จริง**

Dev8StudioSite คือแนวคิดเว็บไซต์ของ Dev8Studio ที่ออกแบบให้ทำหน้าที่มากกว่าเว็บไซต์บริษัททั่วไป

เว็บไซต์ควรเป็นทั้งจุดแนะนำบริการ จุดเริ่มต้นของการค้นหา Requirement พื้นที่ทดลองระบบ และประตูเข้าสู่แนวคิด **Bidirectional Requirement Modeling (BRM)**

แนวคิดสำคัญคือ:

> ลูกค้าไม่จำเป็นต้องรู้ว่าต้องสร้างระบบอย่างไร  
> เพียงอธิบายว่า “กำลังเจอปัญหาอะไร” และ “อยากให้เกิดอะไรขึ้น”  
> Dev8Studio ช่วยทำให้ความคิดนั้นมองเห็น จัดโครงสร้าง ตรวจสอบ และพัฒนาได้จริง

↓

↓

**Requirement**

↓

↓

↓

# 2. บทบาทของเว็บไซต์

Dev8StudioSite มีแนวคิดให้ทำหน้าที่หลายส่วนร่วมกัน

### 2.1 Company Website

เว็บไซต์แนะนำ Dev8Studio และความสามารถในการพัฒนาซอฟต์แวร์

### 2.2 Software Subscription Platform

พื้นที่สำหรับนำเสนอและให้บริการ Software Solutions ในรูปแบบ Subscription

### 2.3 Demo Playground

พื้นที่สำหรับทดลองระบบและผลงานจริงในรูปแบบ Interactive Demo

### 2.4 Requirement Discovery Platform

เครื่องมือช่วยผู้ที่ไม่มีความรู้ด้านเทคนิคอธิบายปัญหาและความต้องการของตนเอง

### 2.5 Comment-to-Requirement System

เปลี่ยนความคิดเห็นจากผู้ใช้ให้กลายเป็น Requirement ฉบับร่างที่มีบริบท

### 2.6 BRM Center

พื้นที่อธิบายและแสดงแนวคิดของ:

**Bidirectional Requirement Modeling (BRM)**

โดยเน้น Traceability และความสัมพันธ์ระหว่าง Business Need, Requirement, System และ Feature

# 5. Website Information Architecture

| หน้า | จุดประสงค์ | ฟังก์ชันสำคัญ |
|---|---|---|
| Home | อธิบายคุณค่าและสร้างความเข้าใจ | ภาพรวมบริการ, ผลงาน, กระบวนการทำงาน, CTA |
| Services | แสดงรูปแบบการให้บริการ | Custom Development, Subscription, Consulting |
| Solutions | แสดงระบบหรือ Solution | ระบบหลังบ้าน, CRM, Booking, Workflow |
| Demo Playground | ให้ทดลองระบบ | Interactive Demo, Scenario, Reset Demo |
| Requirement Studio | ค้นหาและจัดโครงสร้าง Requirement | Guided Conversation, Mind Map, Requirement Wizard |
| Works / Case Studies | แสดงผลงาน | Problem, Approach, Outcome, Demo |
| BRM Framework | อธิบาย BRM | Process, Traceability, Living Framework |
| Pricing / Packages | แสดงรูปแบบแพ็กเกจ | Subscription และ Custom Project |
| Contact | เริ่มต้นการพูดคุย | Contact Form, Requirement Discovery |

> **หมายเหตุ:** แนวคิดเดิมมีหน้า About แต่ไม่ได้อยู่ใน V1 ตาม Governance ปัจจุบัน จึงไม่ควรนำกลับเข้า Scope V1 โดยอัตโนมัติ

# 7. Subscription Solutions

ลูกค้าไม่จำเป็นต้องลงทุนสร้างระบบทั้งหมดตั้งแต่เริ่มต้น

แนวคิด:

- เลือก Solution ที่เหมาะกับธุรกิจ
- สมัครรายเดือนหรือรายปี
- เริ่มจากจำนวนผู้ใช้งานที่เหมาะสม
- ขยายจำนวนผู้ใช้เมื่อธุรกิจเติบโต
- เพิ่ม Module ตามความต้องการ
- ขอ Customization สำหรับองค์กรได้
- มีการดูแลและอัปเดตระบบ

Subscription เป็นแนวคิดด้าน Product Model และต้องแยกออกจาก Production Capability ที่มีอยู่จริง

ห้ามแสดงความสามารถหรือสถานะการให้บริการที่ยังไม่มีการ Implement จริง

# 8. Requirement Discovery

Requirement Discovery มีเป้าหมายเพื่อช่วยลูกค้าที่:

- รู้ว่ามีปัญหา
- รู้ว่าต้องการปรับปรุงอะไร
- แต่ยังไม่รู้ว่าต้องสร้างระบบอย่างไร

กระบวนการควรเป็น:

```text
เล่าปัญหา
   ↓
ถามคำถามเพิ่มเติม
   ↓
ทำความเข้าใจผู้ใช้งาน
   ↓
ทำความเข้าใจเป้าหมาย
   ↓
ค้นหา Business Rules
   ↓
จัดโครงสร้าง Requirement
   ↓
ตรวจสอบความเข้าใจร่วมกัน
   ↓
Requirement ที่พร้อมนำไปออกแบบและประเมิน
